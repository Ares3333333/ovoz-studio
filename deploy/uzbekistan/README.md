# Запуск в Узбекистане: чек-лист локализации ( production в РУз )

Проверено живыми источниками (agent-reach/Exa, 29.09.2026):

- **ЧРП РУз ЗР-547 «О персональных данных», статья 27¹** — в силе по действующей
  редакции lex.uz: персональные данные граждан РУз при обработке с использованием
  информационных технологий **должны собираться, систематизироваться и храниться
  в технических средствах, физически located на территории Республики Узбекистан**,
  а базы — **регистрироваться в Государственном реестре баз персональных данных**
  (уведомительный порядок через уполномоченный госорган).
- **ЗРУ-1125 от 26.03.2026** — свежие поправки к тому же Закону (реестр, условия
  хранения/обработки, требования к операторам). Локализация НЕ отменена.
- Трансграничная передача — только в случаях, определяемых Кабинетом Министров.
- Ответственность за нарушение (разъяснение национального облака UzCloud):
  штрафы и блокировка ресурса. Именно из-за ст. 27¹ в РУз не работают PayPal/Stripe.
- Регистратор/надзор: уполномоченный государственный орган в сфере защиты ПД при
  Кабинете Министров (Центр защиты персональных данных).

## Что это значит для Ovoz AI Studio

| этап | где жить | законность |
|---|---|---|
| Тест/демо (только ты, реальных пользователей нет, ПД третьих лиц не обрабатываются) | бесплатный foreign VPS (Oracle/HF/Render) | риски близки к нулю — нет субъектной базы; ссылку наружу не анонсировать |
| Продакшн с первыми узбекскими пользователями | ВМ в ЦОД РУз (UzCloud / TSUCOS / частые ЦОД, вход ~$5–15/мес, уточнить прайс) | обязателен: storage + реестр |

Код и инфраструктура НЕ меняются: тот же `docker compose` и `deploy/oracle/setup.sh`
(переименуется в generic-linux) работают на узбекской ВМ — меняется только география.

## Чек-лист перед продакшном в РУз

1. [ ] ВМ в РУз: 2 vCPU / 4 GB минимум для реального ASR (замер: dub job peak 1.07 GB), Ubuntu 24.04.
2. [ ] `setup.sh <домен> <токен_бота>` — домен может быть любым (duckdns/eu.org/купленный
      .uz); юридически значимо местоположение сервера, а не домена.
3. [ ] Регистрация базы в Госреестре ПД: заявление в уполномоченный орган
      (уведомительный); описываем БД «users» (ФИО/контакт, хеши паролей) и «jobs».
4. [ ] Согласие на обработку ПД: чекбокс при регистрации + ссылка на политику
      (в UI уже есть путь i18n uz/ru/en — добавить ключ `consent` и текст).
5. [ ] Права субъекта уже реализованы кодом: экспорт данных (GDPR Art.20-аналог),
      удаление аккаунта со всеми следами, revoke сессий/API-ключей — это +2 балла
      доверия при проверке.
6. [ ] Оплата (Payme/Click) — как отдельный шаг при появлении ключей.

## Осторожность на тест-этапе

- тестовый стенд не анонсировать публично (noindex + общая ссылка только мне/тебе);
- в базе тестовой машины не должно быть чужих ПД — только свои записи;
- дамп с production-данными на foreign VPS — уже нарушение; выгрузок не делать.
